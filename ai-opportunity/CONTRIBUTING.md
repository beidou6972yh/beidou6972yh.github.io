# 贡献指南

欢迎提交场景改进、匿名案例、解析缺陷和规则建议。请勿在公开 Issue、PR 或示例中上传真实客户信息、合同、图纸、内部报价、凭证或 API 密钥。

1. 场景定义位于 `core.js` 的 `STAGES`，说明输入、动作、输出、验收、风险与指标。
2. 评分与收益变更须说明理由和边界，加入覆盖实际风险的测试。不要为了提高推荐率降低风险门槛。
3. 修改解析器时提供合成样本，说明截断、编码、表格与位置影响。
4. 运行 `npm ci && npm test`。更新依赖后运行 `npm run vendor`，保留 lockfile 与第三方许可。
5. 界面应对手机和键盘操作友好，模型输出与用户文本按文本处理。

证据不足时请明确标记，不要添加未经核实的行业收益、成功率或客户案例。
