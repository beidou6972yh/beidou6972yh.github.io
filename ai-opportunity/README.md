# 家居 AI 机会诊断 / Home AI Opportunity

**[在线使用 →](https://beidou6972yh.github.io/ai-opportunity/)** · [示例材料](examples/order-review.csv) · [实现与评估方法](DESIGN.md) · [贡献指南](CONTRIBUTING.md)

面向传统定制家居企业的、以证据为基础的 AI 应用机会诊断工具。通过岗位访谈、数据样本与作业规范，判断哪些场景值得先做试点，给出可追溯材料线索、落地条件和收益情景。

An evidence-led, Chinese-first AI opportunity assessment for the custom home furnishing value chain. Browser-local document extraction, explainable readiness scoring, optional user-configured LLM interviews, and transparent ROI scenarios. No hosted API key or backend is required for the baseline assessment.

## 直接使用

1. 打开 **[网页版](https://beidou6972yh.github.io/ai-opportunity/)**，手机与电脑均可使用，无需安装或登录。
2. 点“体验完整示例”了解流程。所有示例业务、评分和测算参数均为虚构，不是行业基准。
3. 填写岗位、目标与业务问题，选择文件或粘贴脱敏材料。
4. 在场景访谈中确认实际条件，未知项保持“待确认”；无需一次填完 15 个环节。
5. 查看机会排序，对候选场景填写收益参数，导出 Markdown / JSON，或使用浏览器打印为 PDF。

公开代码作为独立子项目保存在 `beidou6972yh.github.io/ai-opportunity`，通过已有 GitHub Pages 发布。该目录可以单独复制为独立仓库，不依赖学术主页的资源或脚本。

## 全链条范围

需求对接 → 营销锁客 → 设计方案 → 报价 → 审单 → 下单 → 拆单 → 排单 → 生产制造 → 质检检测 → 物流运送 → 上门安装 → 售后服务。

**行为审计、经济审计贯穿全部环节。** 另外提供需求—订单一致性、生产—售后质量追溯、订单成本与收支勾稽三个跨环节检查方向。

每个场景包含：输入材料、原子动作、预期产出、人工验收、风险边界和试点指标。没有预设“某部门一定最适合 AI”。

## 两种诊断方式

### 无需密钥的本地初筛

规则式动态提问、相关材料摘录、用户自评排序与收益测算均在浏览器运行。**这不是云端大模型诊断。** 关键词命中仅代表材料相关性，不证明流程成熟或内容正确。无材料时可以访谈，但报告保留证据缺口。

### 可选的模型辅助诊断

在“模型设置”填写兼容 Chat Completions 的基础地址（通常以 `/v1` 结尾）、模型 ID 和密钥。工具会补上 `/chat/completions`，也接受完整端点。

- 每次调用前展示接收服务与完整发送正文，必须主动勾选并确认。
- 模型分析材料、岗位、目标和访谈，返回具体追问与机会建议；模型不能自动改评分或收益。
- 对模型引用逐字核对来源。匹配成功仅表示引文存在，不代表模型推论成立；无法核对的引用标为“无可核对原文”。
- 密钥仅在当前页面内存中，刷新即清除，不写入本机存储、报告、日志或仓库。不会提供公共共享密钥。
- 模型服务必须允许浏览器跨域请求（CORS）；部分供应商不支持直接浏览器调用。连接错误会明确提示，不自动切换到其他服务。
- 本地模型：在本地运行网页，使用 `http://localhost:端口/v1` 或 `http://127.0.0.1:端口/v1`，并配置模型服务允许该本地网页来源。公开 HTTPS 页面可能受混合内容或本地网络权限限制。
- 不内置模型供应商推荐或可用性保证。真实服务调用需要用户的接口和额度。

## 文件支持与边界

| 格式 | 提取范围 | 限制 |
|---|---|---|
| TXT / Markdown / JSON | 文本段落 | UTF-8，必要时尝试 GB18030 |
| CSV / TSV | 表头与数据行 | 最多分析前 300 行，文件最多 10,000 行 |
| DOCX | 正文与表格文字 | 不含图片、批注和页眉页脚 |
| XLSX | 单元格文本与公式缓存值 | 最多 12 表、每表 300 行数据及 200 列；不计算公式，日期可能为序列值 |
| PDF | 文字层及页码 | 前 40 页范围内；不识别扫描图片，复杂表格顺序需核对 |

最多 8 个材料，单文件 8 MB，每材料保留最多 40,000 字符；模型一次最多接收 60,000 字符的材料摘录，实际发送内容在确认窗口展示。Office 解压读取设置额外体积和条目限制。材料可能包括敏感信息，建议上传脱敏样本。

不支持 `.doc`、`.xls`、CAD、图片 OCR、自动几何校核、直接操作 ERP/MES、自动审批、设备控制或正式审计意见。

## 评分方法

用户提出的四个起点：已有可用数据与知识、有处理规范、有明确产出、存在重复原子动作。

在此基础上增加可复核性、实施便利度、风险可控程度，再结合当前业务目标。

| 可行性维度 | 权重 |
|---|---:|
| 数据与知识可用性 | 20% |
| 作业规范明确度 | 15% |
| 产出与验收清晰度 | 15% |
| 动作重复程度 | 15% |
| 结果可复核性 | 15% |
| 实施便利度 | 10% |
| 风险可控程度 | 10% |

各项为 1—5 级，线性映射到 0—100。可行性按已回答维度的权重归一化，显示权重覆盖率。**未知项不算 0，也不假定为成熟。** 至少回答 4 个维度并填写当前目标的业务价值，才生成初筛优先分：`可行性 × 70% + 目标价值 × 30%`。

风险或结果复核为 1—2 级时，不作为优先验证候选，先补控制措施。不足 100% 覆盖的分数属于初步候选，完整度不同不能视作同等证据。该方法未经行业实证校准，评分来自用户自评，不应解释为成功概率。

## 收益测算

```
月净节省工时 = 月任务量 × AI覆盖率 × (原耗时 − 复核耗时) ÷ 60
工时价值 = 月净节省工时 × 人工综合小时成本
可兑现人工节约 = 正的工时价值 × 可兑现比例
若增加工时，按全额新增人工成本扣除，不乘可兑现比例
月净现金收益 = 可兑现人工节约 + 月减少损失 + 月新增毛利 − 月运行维护成本
静态回本月数 = 一次性投入 ÷ 正的月净现金收益
首年净收益 = 12 × 月净现金收益 − 一次性投入
```

月净收益不为正时显示“当前假设不回本”。所有输入都必须明确填写；不涉及的金额填 0，不会使用占位示例值。成本应覆盖模型、系统、集成、资料整理、维护与人工复核，避免漏计；复核时间已单列，不要再重复算入月维护。

保守/积极情景将覆盖率、减少损失、新增毛利乘以 70%/110%，覆盖率上限 100%，其他成本保持不变。它们是**用户假设的敏感性情景，非统计置信区间**。不含贴现及税务建模。跨环节共享工时和收益不自动求和，避免重复计入。

## 本地运行与测试

已提交所有运行所需静态依赖，不依赖外部 CDN。使用 Node.js 22 或更高版本：

```bash
cd ai-opportunity
node server.js
# 浏览器打开 http://127.0.0.1:8080/
```

开发与复现：

```bash
npm ci
npm run vendor
npm test
```

也可将整个目录交给任意静态服务器；不要通过 `file://` 直接打开，浏览器的模块加载限制会阻止运行。`server.js` 仅监听本机，拒绝目录穿越和敏感路径，不提供模型代理。

## 数据与隐私

默认会话只存在当前页面内存。点“保存到本机”才会写入当前浏览器的 localStorage，包含材料摘录与回答；点“清空诊断”删除该存储。不要在共享设备上保存真实业务材料。保存不是账户同步，也不是加密保险箱。

无遥测、无后台上传、无用户账户数据库。加载网页会像普通网站一样由 GitHub Pages 处理 HTTP 请求；本地材料解析不向 GitHub 发送文件。启用模型后，已确认的内容直接发送给用户指定的服务，受该服务的数据政策约束。

报告包含材料摘录，分享前应检查敏感信息。发布仓库只包含程序、文档和虚构示例，不包含用户诊断数据或 API 密钥。
